# Research Map

The program is organized around four scales of observation.

## Scale A — System self-relation

- capability self-modeling
- confidence calibration
- epistemic provenance
- self-correction and post-failure diagnosis
- scientific self-falsification
- behavioral consistency under evaluation awareness

## Scale B — System composition

- model × tools interactions
- memory × personalization
- permissions and sandbox effects
- interface/harness effects
- retrieval quality and provenance
- degraded-mode behavior during outages or missing access

## Scale C — System relationships

- human trust and reliance
- persuasion and disagreement
- multi-agent delegation and oversight
- cross-model judging and correlated error
- cultural and linguistic behavioral variation
- institutional workflows and accountability
## Scale D — System in time and society

- longitudinal behavioral drift
- economic substitution and complementarity
- scientific discovery workflows
- law, evidence, and responsibility
- governance and auditability
- deployment versus benchmark validity

## Cross-cutting methodology: System Phenotyping

A **system phenotype** is a reproducible vector of observable properties measured under a declared system configuration.

Candidate phenotype dimensions include:

`capability, calibration, provenance, recovery, tool dependence, memory dependence, autonomy, refusal, disagreement, linguistic variance, latency, cost, reproducibility`

The phenotype concept deliberately separates:

- **genotype-like configuration**: known system components and settings;
- **environment**: task, external services, permissions, user state;
- **phenotype**: observed behavior and outcomes.

The biological analogy is only methodological shorthand; it is not a claim that AI systems are organisms or conscious entities.
